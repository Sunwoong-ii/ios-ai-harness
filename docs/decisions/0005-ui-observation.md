# 0005. 앱 화면 확인은 AXe와 simctl을 스크립트로 감싸서 한다

- 상태: 채택
- 날짜: 2026-11-08

## 배경

- 에이전트는 화면을 볼 수 없다. verify는 컴파일과 단위 테스트까지만 확인하므로, UI를 바꾼 뒤 화면이 의도대로 나오는지는 모른다([principles.md](../principles.md) 원칙 8).
- 화면을 확인하려면 네 가지가 필요하다.
  - 앱을 시뮬레이터에 설치하고 실행하기
  - 화면에 있는 요소(버튼, 텍스트, 값)를 텍스트로 읽기. 이 목록을 접근성 트리라고 한다. 앱이 VoiceOver에 알려주는 정보라서 라벨·식별자·값·위치가 들어 있다.
  - 요소를 눌러 화면을 이동하기
  - 스크린샷 찍기
- Apple의 `xcrun simctl`은 설치·실행·스크린샷까지만 한다. 접근성 트리를 읽거나 탭하는 기능은 없다.

## 검토한 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| **AXe + simctl** | AXe는 접근성 트리 조회, 식별자로 탭, 입력, 스크린샷을 하는 단일 바이너리다(MIT). Homebrew로 설치하고, 릴리스는 Developer ID 서명과 공증을 받는다. 텔레메트리가 없다 | 사실상 개발자 한 명이 관리한다. Apple 비공개 API(Meta idb의 FBSimulatorControl)를 써서 Xcode가 크게 바뀌면 깨질 수 있다 |
| MobileBuildMCP(구 XcodeBuildMCP) CLI | 빌드·실행·UI 자동화·로그를 한데 묶었다 | UI 자동화는 내부에서 AXe를 쓴다. 빌드·테스트는 하네스 스크립트와 겹친다. Node가 필요하고 Sentry 텔레메트리가 기본으로 켜져 있다. 2026-09 이름이 바뀌면서 npm 패키지가 2.7.0에서 멈췄다 |
| MobileBuildMCP를 MCP 서버로 연결 | Codex 샌드박스에서도 시뮬레이터를 다룰 수 있다 | Sentry 실험에서 셸 방식보다 토큰이 약 2배 들었다 |
| Xcode 27 `device-interaction` 스킬 | Apple이 만든 스킬이다. 스크린샷, UI 계층, 터치로 앱을 확인한다 | Xcode 27을 띄우고 프로젝트를 열어 둬야 하고, 시뮬레이터가 27.0 이상이어야 한다. CI나 화면 없는 실행, 워크트리별 병렬 세션에 맞지 않는다. 로컬 Xcode는 26.6이다 |
| Claude 데스크톱 앱의 시뮬레이터 도구 | 설치가 필요 없다 | 데스크톱 앱에서만 쓸 수 있다. 터미널 CLI와 Codex에는 없다 |

## 결정

- `scripts/harness/run`과 `scripts/harness/ui`를 만들고, 그 안에서 simctl과 AXe를 부른다.
  - run: 빌드 → 시뮬레이터 부팅 → 설치 → 실행. simctl만 쓴다.
  - ui shot: 스크린샷. simctl만 쓴다.
  - ui tree·tap·type: AXe를 쓴다.
- **AXe는 선택 의존성이다.** 없거나 버전이 낮으면 ui tree·tap·type만 설치 명령을 알려주고 멈춘다. run과 shot은 AXe 없이 동작한다.
  - 최소 버전은 확인한 1.8.0으로 둔다.
  - 설치는 공증받은 Homebrew 릴리스로 한다(`brew install cameroncooke/axe/axe`). 다른 도구에 들어 있는 사본은 공증되지 않았을 수 있다.
- AXe를 부르는 곳은 ui 스크립트 하나로 모은다. 나중에 다른 도구로 바꿔도 이 스크립트만 고친다.
- 출력은 build·test처럼 줄인다.
  - 접근성 트리 원본(시뮬레이터 홈 화면 기준 345KB, 요소 246개)은 파일로 남기고, 라벨·식별자·값이 있고 화면 안에 있는 요소만 한 줄씩 보여준다(같은 화면 22줄, 1KB).
  - 스크린샷은 `sips`로 긴 변 1200px JPEG로 줄인다(3.2MB → 98KB).
- 화면 이동은 좌표 대신 접근성 식별자나 라벨로 한다. 좌표는 기기 크기와 레이아웃에 따라 바뀐다.

## 결과

- 좋아지는 점
  - 에이전트가 UI를 바꾼 뒤 화면 요소와 스크린샷으로 결과를 확인할 수 있다.
  - Xcode 26에서도, 화면 없이도 동작한다. 사람과 에이전트가 같은 명령을 쓴다.
- 비용과 위험
  - AXe를 따로 설치해야 한다. 설치하지 않은 프로젝트에서는 화면 요소를 읽을 수 없다.
  - Xcode가 바뀌어 AXe가 깨지면 고쳐질 때까지 tree·tap·type을 쓸 수 없다. 스크린샷은 계속 된다.
  - Codex의 read-only 샌드박스에서는 셸로 시뮬레이터를 다룰 수 없다. Codex 어댑터(후보 16)에서 다룬다.
- 다시 볼 때
  - Xcode 27로 올리면 `device-interaction`과 비교한다(백로그의 Xcode 27 어댑터).
  - AXe 관리가 멈추거나 자주 깨지면 다른 도구로 바꾼다.
