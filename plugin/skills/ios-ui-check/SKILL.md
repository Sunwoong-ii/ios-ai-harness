# 화면 확인

빌드와 단위 테스트는 화면이 의도대로 나오는지 알려주지 않는다. 화면을 바꿨으면 앱을 실행해 직접 보고, 본 것을 근거로 보고한다.

## 명령

| 할 일 | 명령 |
|---|---|
| 빌드 → 설치 → 실행 | `scripts/harness/run` (앱 인자: `scripts/harness/run -- -인자`) |
| 화면 요소 보기 | `scripts/harness/ui tree` |
| 누르기 | `scripts/harness/ui tap --id 식별자` / `scripts/harness/ui tap --label 라벨` |
| 입력란에 입력 | `scripts/harness/ui type "텍스트"` (먼저 입력란을 누른다. 한글도 된다) |
| 슬라이더 옮기기 | `scripts/harness/ui slider --id 식별자 0~100` (스위치는 `tap`) |
| 스크린샷 | `scripts/harness/ui shot 이름` → 출력된 경로를 Read 도구로 연다 |

`ui tree`는 요소마다 `타입 "라벨" #식별자 =값 (비활성) @x,y 너비x높이`를 한 줄씩 보여준다.

## 절차

1. `scripts/harness/verify`로 빌드와 테스트를 먼저 통과시킨다.
2. `scripts/harness/run`으로 실행한다. 프로젝트 규칙(`.claude/rules/project/`)에 실행 인자나 시나리오가 있으면 따른다.
3. `ui tree`로 첫 화면을 확인한다.
4. 바꾼 화면까지 이동한다. tree에 나온 `#식별자`가 있으면 `--id`로, 없으면 `"라벨"`로 누른다. 누를 때마다 `ui tree`로 도착했는지 확인한다.
5. 확인한다.
   - 문구, 값, 활성 상태, 요소가 있는지는 tree로 본다. 텍스트라서 정확히 비교할 수 있다.
   - 레이아웃, 색, 잘림, 겹침은 `ui shot`으로 본다. 스크린샷은 토큰이 많이 들어서 화면 하나에 한두 장만 찍는다.
6. 보고한다: 실행한 명령, 확인한 요소나 스크린샷 경로, 기대와 다른 점. 확인하지 못한 부분은 못 했다고 쓴다.

## 주의

- 좌표로 누르지 않는다. 기기 크기와 레이아웃에 따라 바뀐다. 누를 요소에 식별자도 라벨도 없으면 보고에 적고, 식별자 추가는 사용자에게 제안한다.
- `.harness/out/ui/tree.json`(원본)을 통째로 읽지 않는다. 요약에 없는 속성이 필요할 때만 jq로 필요한 부분을 본다.
- 위치 권한 같은 시스템 알림이 화면을 가리면 tree에 나온다. 라벨로 눌러 닫는다.
- 앱의 print·Logger 출력은 `.harness/out/app.log`에 있다. 크래시나 에러가 의심되면 끝부분을 본다.
- `ui type`은 클립보드로 붙여 넣는다. 입력한 뒤 `ui tree`로 입력란의 값이 맞는지 본다.
- AXe가 없다는 안내가 나오면 설치는 사용자에게 맡긴다. 그동안은 `run`과 `ui shot`으로만 확인하고, 그 사실을 보고한다.
